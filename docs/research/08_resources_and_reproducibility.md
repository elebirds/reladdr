# 资源、复现与首批执行清单

当前授权为文档／协议整合、代码子包重构与离线工程验收，**不启动模型实验、不下载模型、不租用算力**。
不生成本批研究数据或运行其 prepare-only；工程测试可在临时目录验证既有 CLI 和记录契约。
本页是 B03、M03 与有限 M04 的唯一汇总清单和调用预算；数据/端口细则分别见对应协议。
完整研究树见 [06](06_experimental_design.md)，开发工具见 [开发说明](../development.md)。
下述未执行额度是后续执行计划，不表示资源已授权或实验已完成。

## 2. 首批调用预算：正常路径 274 次尝试

统一按实际模型前向**尝试**计账，失败也占用额度。每个前向只进入一类：

\[
F=U+P M+F_{\mathrm{mid}}+F_{\mathrm{checks}}.
\]

- \(U\)：第一次评估的自然输入；一张图的不同问题仍分别耗用前向，但不是独立场景族。
- \(P M\)：正式因果干预的有向配对数乘每对干预条件数；多个节点时求和。
- \(F_{\mathrm{mid}}\)：补取中间量或产生两阶段中介轨迹的前向；本批只有已见自然输入的重新捕获。
- \(F_{\mathrm{checks}}\)：端口/恢复等工程尝试，包括工程检查中的自然基线、自身替换与故意异常。
  不再重复计入 \(U\)、\(P M\) 或 \(F_{\mathrm{mid}}\)。

| 项目 | \(U\) | \(P M\) | \(F_{\mathrm{mid}}\) | \(F_{\mathrm{checks}}\) | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| B03 初批：16 族 × 2 配色 × 6 问 | 192 | 0 | 0 | 0 | 192 |
| M03：两输入的固定端口验收 | 0 | 0 | 0 | 34 | 34 |
| M04：16 个 B03 输入重捕获 + 32 个局部换色输入 | 32 | 0 | 16 | 0 | 48 |
| **正常路径** | **224** | **0** | **16** | **34** | **274** |
| 仅 B03 符合预定追加条件时：另 16 族 | +192 | 0 | 0 | 0 | +192 |
| 仅 M03 技术失败修复后的受影响复检，最多 | 0 | 0 | 0 | +8 | +8 |

因此正常首批为 **274**；触发唯一 B03 追加后为 **466**。把 M03 修复预留全部用尽时，
对应硬上限为 **282 / 474**。追加和修复都不是默认调用，不因预算尚有余额而运行。
M03 的 34 次包括 2 次故意中止的异常测试，不代表 34 个完整成功前向；真实成本另记录。

B03 的配色变体、M04 的局部换色与同图多问均沿用场景族归属。M04 有 48 次自然前向，
只有 4 个族；本批前向总量不是独立样本量。旧 14 个 E02/E03 run 的 12,840 次前向是
历史成本，不抵扣或加入本表，不构成新规模的证据。

### 暂停、失败和重试的明确账本

| 退出点 | 已用/允许的调用范围 | 下一步 |
| --- | --- | --- |
| 离线实现/真值/权限检查不通过 | 0 | 修复离线缺口；没有模型执行 |
| B03 初批完成但任一配对覆盖为 0 | 192 | 暂停当前成功机制路线，不启动 M03/M04 |
| B03 仅达到一次追加条件，追加后仍不达标 | 384 | 保存全量行为结论，不继续扩量 |
| B03 中途技术失败 | 至多 192；已启用追加时累计至多 384 | 立即停止；不把未完成问题记为错误答案，不自动重试 |
| M03 出现非预定异常/数值失败 | B03 已用 192 或 384，加实际已用 checks；正常检查最多 34，含修复总 checks 最多 42 | 停止剩余调用；一次有依据的离线修复后只重跑受影响检查 |
| M03 未通过即结束 | 不追加时至多 234；已追加时至多 426 | M04 为 0；保留失败端口及恢复状态 |
| M04 捕获中途失败或完成后无可用候选 | 本节点最多 48，不因失败补足 48 条成功记录 | 不自动重捕获、不加 head patch；按 M04 的一次同批记录分析规则决定 U 出口 |

技术失败消耗调用但不制造科学样本。B03/M04 没有额外自动重试额度；修复后的重启或缺失输入
补做必须重新核算剩余额度与必要范围，不以重跑整批恢复整齐表格。M03 的最多 8 次修复
专属其受影响检查，不可挪给模型/数据搜索。恢复后有效记录可复用，不能为安心重复调用。
预算耗尽、状态无法恢复或所需检查超出额度时停止，交付具体缺口后再决定是否修改计划。

## 3. 资源是实测对象，不是按旧秒数承诺

本批固定 336 px，预期 144 视觉 token、batch=1、BF16、SDPA、参数冻结、无训练和反向。
M03 仅捕获声明的层/行与完整归一化所需 K/V；M04 按协议逐层记录紧凑自然统计，不默认
保存全层全注意力矩阵。最初几次已计入预算的前向同时记录加载/前向/捕获/落盘耗时及峰值
allocated/reserved 显存，不额外开一批 benchmark。

历史 [GPU 工程初调](../reports/gpu_smoke_2026-10-19.md) 在 256 视觉 token、BF16、SDPA
纯推理下记录峰值 allocated 15.56 GiB、reserved 15.82 GiB。它不能保证本批全层统计的峰值，
也不能换算正式研究的总 GPU 小时。本批先报告真实耗时和成本，再为下一节点估算。

后续需要局部反向或 S01 搜索时，可参考下表的**未验证扩量估计**；它不是当前购买或租用建议：

| 部分 | 后续规划参考 | 需要实测的影响 |
| --- | --- | --- |
| GPU | 单张约 48GB；80GB 为扩量余量 | 激活、反向范围、后端与重算策略 |
| 系统内存 | 32GB 可试起步；64GB 更宽裕 | 分片加载、按批落盘，不必大于显存 |
| CPU | 约 12–16 vCPU | 数据处理、后续搜索求解与统计 |
| SSD | 约 500GB 可用空间 | 权重、数据、选定激活与独立备份 |

正式进入反向/搜索时再测其实际流程。冻结参数省去参数梯度/优化器状态，不等于激活梯度
无需计算图。不要为了适配显存默认量化；不要在本批安装 GPU extra 到 Mac。

[官方权重索引](https://huggingface.co/Qwen/Qwen2-VL-7B-Instruct/blob/main/model.safetensors.index.json)
列出的张量总大小 16,582,751,232 bytes 不是完整运行显存，不能据此承诺 24/32GB 适用。
[NVIDIA 官方 4090 标准配置](https://www.nvidia.com/en-us/geforce/graphics-cards/40-series/rtx-4090/)
为 24GB；历史用户节点报告 49,140 MiB。未来若选择同类平台规格，核对实际单卡容量与
稳定性保障，不从营销名称继承设备事实。

## 4. 每次运行的来源链与保存

公共运行层已能记录配置、代码/依赖、seed、状态和耗时；本批新增组件须补齐其有效来源：

1. **代码**：commit、相关 dirty 状态/改动、真实入口和命令。没有实现的入口不提供假命令。
2. **依赖**：项目锁文件、Python、模型依赖版本、驱动/CUDA、GPU 和 attention backend。
3. **模型**：checkpoint 与 processor 的各自来源/revision、dtype、模板、实际视觉 token 数。
4. **数据**：生成器版本、seed、完整对象/RGB/bbox 和问题清单、family ID、划分与追加是否启用。
5. **接口**：零起点 block 层、query/KV head、物理 token/slot、mRoPE 前后、mask、完整分母、
   donor、重算范围及端口顺序。
6. **结果**：逐输入 greedy/candidate 结果、聚合统计、失败、attempted/succeeded/failed 计数、
   各段耗时、峰值显存、产物位置和工程误差分布。
7. **解释**：报告链接真实 run ID；区分数据/实现失败、科学反例、未确定和等价合并。

改变输入、端口、donor、精度、模板或后端后，不能无条件继承旧缓存或校验证据。
Git 只保存代码、小配置、协议和有依据的解释；`data/`、`runs/`、权重与大激活不提交。
重要产物独立备份，尤其不能只留在临时 GPU 磁盘。

本批默认 tracking/artifact 上传关闭。需要 MLflow 时仍先保存本地记录，上传失败明确标记，
不影响本地结果留存。服务地址与认证使用批准机制；凭据、整个环境变量集合和私有数据
不进入日志或 Git。此前真实 OSS 文件链路仍待验证，不在本批接入义务中。
