# 资源、复现与风险

本页保留机制/搜索扩量估计；纯推理已完成一次 [GPU 工程初调](../reports/gpu_smoke_2026-10-19.md)：
256 视觉 token、BF16、SDPA 下峰值 allocated 15.56 GiB、reserved 15.82 GiB。
激活缓存、干预和反向的资源需求仍需分别测量。开发工具用法见
[开发说明](../development.md)，数据和指标的科学协议见 [06](06_experimental_design.md)。

## 1. 机制与搜索扩量的机器估计

按 Qwen2-VL-7B-Instruct、BF16、冻结参数、单图短问答、选择性激活/梯度分析估计：

| 部分 | 首轮建议 | 影响 |
| --- | --- | --- |
| GPU | 单张约 48GB 显存；80GB 为扩量余量 | 中间激活和局部反向比纯推理占更多空间 |
| 系统内存 | 32GB 可试起步；64GB 更宽裕 | 分片加载、按批落盘；不必大于显存 |
| CPU | 约 12–16 vCPU | 数据处理、分式求解与统计 |
| SSD | 约 500GB 可用空间 | 权重、数据、选定激活和运行产物 |

初始视觉 token 预算计划约 256–1024，batch=1，只保存选定接口。真实显存需求还依赖
后端、序列长度、梯度范围和缓存策略。冻结参数省去参数梯度/优化器状态，不代表不保存
求激活梯度所需的计算图。

模型的 [官方权重索引](https://huggingface.co/Qwen/Qwen2-VL-7B-Instruct/blob/main/model.safetensors.index.json)
列出总张量大小 16,582,751,232 bytes；它不是完整运行显存。不要据此承诺 24/32GB 一定装下
所有干预和反向流程。也不为塞进显存默认量化，否则研究对象的计算发生改变。

若租用“4090 48GB”，应确认是可用的单卡容量及平台稳定性保障；
[NVIDIA 官方 4090 标准配置](https://www.nvidia.com/en-us/geforce/graphics-cards/40-series/rtx-4090/)
为 24GB。本次用户提供的 AutoDL 节点报告 49,140 MiB；以当次设备记录为准。

## 2. 在扩量前测真正的瓶颈

模型接入时用代表性样本测：纯前向、选定激活提取、一次实际 patch、一段所需反向、完整
下游重算。记录峰值分配/保留显存和阶段时间。只有受影响实验需要重测，不重复无关全矩阵。

关注风险与行动：

- 全层 attention/激活保存导致内存与磁盘膨胀：按头/行/子空间选择，不默认全量常驻。
- 不必要地使用完整 Jacobian：先计算地址方向的 JVP/VJP。
- 求解分支占去 GPU 节省：包含 CPU 求解时间，保留可行候选与停止原因。
- 32GB 系统内存不足以常驻缓存：按批写盘，减少同时运行进程；不是直接削减研究目标。
- 后端 hook 不覆盖真实计算：验证读取位置和原生重算一致性，再解释效应。

已使用用户租用节点完成一次初调；当前没有足够数据估算正式机制/搜索实验的总 GPU 小时。

## 3. 每次运行的来源链

公共层已记录配置、代码/依赖、seed、状态与耗时；具体研究组件仍需补齐下列来源：

1. **代码**：commit、相关 dirty 状态/代码改动，入口与命令。
2. **依赖**：项目锁文件版本、Python、模型依赖版本、驱动/CUDA、GPU 与 attention backend。
3. **模型**：checkpoint/processor 固定 revision、dtype、量化情况、模板和视觉 token 预算。
4. **数据**：生成器/数据版本、scene-family ID、完整问题清单、固定划分、实际 seed。
5. **干预**：物理层/头/槽位、位置编码前后、组定义、donor、重算范围与接口顺序。
6. **结果**：逐样本预测、聚合指标、失败、耗时/调用数、峰值显存与产物位置。
7. **解释**：研究文档链接 run ID，说明比较和判断变化。

版本、ID 和清单应能恢复数据、模型与运行来源。
改变图像/问题/端口/donor/精度/后端后，不能无条件继承缓存或旧证据。

## 4. 保存与协作

- Git 保存代码、小配置、文献链接、数学规格和有依据的研究解释。
- `data/`、`runs/`、权重与大体积激活不提交 Git。重要原始产物独立备份，尤其是临时 GPU 磁盘。
- MLflow 汇总参数、指标和选定小产物；本地记录先保存，上传失败明确标记。
- 服务器地址与认证通过批准机制注入。凭据、整个环境变量集合和私有数据不进入记录。
- 不把同一组论文/结论在多个文档手动维护；共享讨论材料链接本目录的相应章节。

## 5. 后续实现前仍需决定的技术项

公共运行层已完成，以下研究组件与真实服务接入归属后续实施：

- **模型适配负责人（后续实现者）**：推理栈与模型来源已记录；继续实现 cache/hook API 和原生 token 映射。
- **任务实现负责人**：明确实际渲染参数、答案可区分性、分词读出、场景分组与测试规模。
- **机制实现负责人**：独立标定地址接口，验证不同阶段的基能否支持复合算子检验。
- **搜索实现负责人**：精读 R12 的完整表述，选定通用求解基线，核对浮点下界、停止与缓存复用。
- **记录集成负责人**：本地记录、可选同步、实际参数/指标读回已验证；真实 OSS 文件链路仍待验证。

当前没有指派外部协作者；三形状与推理组件已有初调实现，原生干预及搜索组件仍待实现。
