# 资源、复现与首批执行清单

当前只做协议修订与只读组合分析，**不启动模型实验、不下载模型、不租用算力**。
B03 v2 的配色容量和旧碰撞已用内存组合复算核对，未创建研究数据或实现新入口。
本页的额度是未来执行建议，尚未获得模型执行授权。编号／依赖见 [06](06_experimental_design.md)。

## 1. 第一批先得到消费者证据，再做一次载体鉴别

| 顺序 | 责任与交付 | 验收与下一步 |
| --- | --- | --- |
| 离线准备 | 任务实现者完成 [B03](protocols/B03_Reference_Disambiguation.md) v2 原图与单换色闭包清单、真值及记录入口；执行者补尝试账本 | 9 族闭包互不重叠，18 原图、108 输入；角色/变体和唯一输入对应；实际渲染、CPU 测试通过 |
| B03 自然行为 | 执行者运行全量108输入，保留所有错误；分析者按预注册规则选 M04 成功配对和错误诊断锚点 | 报实际覆盖，不以六类各四族作为统一门槛；无可用锚点时交付缺口 |
| M04 所需端口 | adapter 维护者完成 [M03 consumer_write](protocols/M03_Native_Instrumentation.md) 的针对性验收 | 现有 pre-O/MLP 捕获、原始自身替换、hook 异常清理与恢复通过；不等 Q/K/V 平台 |
| M04 自然捕获＋局部确认 | 机制分析者用既有写入端口比较 g/o/k 换色，再冻结候选做相同范围的写入替换 | 分开真值目标、输出对应对象假说和控制对象；交付实际消费者及其角色特异证据 |
| 条件性 M05 首测 | 有 attention 消费者且可对齐问题对时，补该接口的 reader_attention 观测；登记两种不同载体预测 | 两端重建及恢复通过后，固定 recipient 做两种行级交叉；结果直接反馈 M06 的生产路径问题 |
| 批次交付 | 总负责人将消费者、候选计算、证据缺口和下一项分歧预测写回现有记录 | 没有分歧预测不扩交叉矩阵；若 MLP 主导，沿其实际输入推进，不强套 Q/K/V |

B03 实现与已有写入端口的离线检查可并行；GPU 只按实际依赖推进。
真正使用来源竞争时才新增 post-mRoPE/全来源重建；逐头 projection 改写和 receiver 私有边
不在默认第一批。新层/头定位、原位解释与更多鉴别条件随后按具体问题分批登记。

所有实际执行先核对权重与 processor 来源、锁定依赖、BF16/SDPA、真实 token/role、单 token
颜色答案和可恢复状态。不默认换版本、量化或下载。当前 canonical 入口没有历史兼容层，
历史 run 和报告继续保留执行时身份。

## 2. 首批预算：基础108，按有效锚点和消费者启用后续

调用按实际模型前向**尝试**计账，失败也消耗额度；每次只进入一类：

\[
F=U+F_{\mathrm{patch}}+F_{\mathrm{mid}}+F_{\mathrm{checks}}.
\]

- U：首次评估的唯一图像＋完整提示＋运行条件；同图不同问分别耗用调用，不是独立族。
- F_patch：科学干预／局部替代调用，按实际配对和条件计数。
- F_mid：已见输入缺少张量时的重捕获，或产生中介轨迹的调用。
- F_checks：工程基线、原始／重建自写、异常和恢复；不重复计入其他类。

### 本批资源分配

这些是本批计划名额，不是科学通过门槛或永远不能增加的候选数：

- M04 成功锚点：优先 **4 个不同族的正确配对**，N_c≤8 条输入；无配对时可按协议取单题，
  不足时使用实际数。没有新的正确题时不靠重跑补齐。
- 错误诊断：N_e≤2 条可唯一对应非参照对象的错误输入，每族一条；不存在则为0。
- 局部确认：计划比较 C≤2 个注册消费者接口，一个接口可为有依据的联合头／位置组。
  候选不止两个不意味着其他候选错误；后续投入按区分价值登记。
- M05 首测：一个有向配对、一个已确认的 attention 接口。两种交叉都写 recipient0，
  不是两个方向。没有对齐接口或分歧预测则不执行。

| 项目 | U | F_patch | F_mid | F_checks | 本批上界 |
| --- | ---: | ---: | ---: | ---: | ---: |
| B03：9族 × 2配色 × 6问 | 108 | 0 | 0 | 0 | 108 |
| consumer_write：固定一输入的检查 | 0 | 0 | 0 | 6 | 6 |
| M04：角色换色自然捕获 | 2N_c+3N_e | 0 | N_c+N_e | 0 | 32 |
| M04：每接口、每角色同范围替换 | 0 | C(2N_c+3N_e) | 0 | 0 | 44 |
| M05 条件性首测：补观测、自重建、恢复、交叉 | 0 | 2 | 2 | 3 | 7 |
| **计划全部名额启用** | **130** | **46** | **12** | **9** | **197** |

没有错误诊断而其他名额全部启用时为 **177**。只有 B03 可用时为108；没有候选或证据
已足够时不为花完额度补调用。6次 consumer_write 包括一次故意中止的异常，不是6条科学预测。

在 M05 前必须已有同版本完整末位置 logits、接口原生 y 和适用的原始 y 自写证据；否则
相应补捕获／检查单列增量，不能把它隐藏进七次。自重建写回的误差和严格 no-op 分开验收。
实际执行前据冻结清单复算唯一输入和次数，重复输入转为复用／重捕获，而不增加 U。

v1 的274次正常路径、16+16族追加和8次专属复检额度已由本表取代。
**建议本批调用上限为197次尝试**。技术修复可以使用登记后的剩余额度；需要提高上限时
说明失败原因、受影响检查、增量成本及新的科学比较，再取得相应授权。超过额度是批次暂停，
不是机制失败。资源额度不强制某个候选只能修订一次，也不以“第九次复检”作为结论。

### 暂停与继续按实际原因决定

- 数据归属、真值、记录或 hook 状态出错：暂停受影响调用，修复后复用有效记录，重验失效部分。
- 行为覆盖有限：分析已有明确锚点并报告范围；没有锚点时给出具体缺口，不自动添一池图。
- 自然与局部响应矛盾：保留反例，选择能区分角色、兼容性或旁路的下一项比较。
- 重建误差掩盖 M05 分歧：先改善该测量，不执行无法解释的交叉。
- 额度耗尽：提交真实尝试账本和下一批的新增证据／区分预测；最终测试不参与这些修订。

前向总量不等于独立样本量；最多仍是这9个发现族。162张闭包图只是所有权预留，
没有162张图的模型调用。旧14个 E02/E03 run 的12,840次前向只属于历史成本。

## 3. 资源是实测对象，不是按旧秒数承诺

本批固定 336 px，预期 144 视觉 token、batch=1、BF16、SDPA、参数冻结、无训练和反向。
M04 先捕获声明写入与末位置 logits；只有选定 M05 消费者才补其读取行和完整归一化所需 K/V，
不默认保存全层全注意力矩阵。最初几次已计入预算的前向同时记录加载/前向/捕获/落盘耗时及峰值
allocated/reserved 显存，不额外开一批 benchmark。

历史 [GPU 工程初调](../reports/gpu_smoke_2026-10-19.md) 在 256 视觉 token、BF16、SDPA
纯推理下记录峰值 allocated 15.56 GiB、reserved 15.82 GiB。它不能保证本批全层统计的峰值，
也不能换算正式研究的总 GPU 小时。本批先报告真实耗时和成本，再为下一节点估算。

后续需要局部反向或 S01 搜索时，可参考下表的**未验证扩量估计**；它不是当前购买或租用建议：

| 部分 | 后续规划参考 | 需要实测的影响 |
| --- | --- | --- |
| GPU | 单张约 48GB；80GB 为扩量余量 | 激活、反向范围、后端与重算策略 |
| 系统内存 | 32GB 可试起步；64GB 更宽裕 | 分片加载、按批落盘，不必大于显存 |
| CPU | 约 12–16 vCPU | 数据处理、后续搜索求解与统计 |
| SSD | 约 500GB 可用空间 | 权重、数据、选定激活与独立备份 |

正式进入反向/搜索时再测其实际流程。冻结参数省去参数梯度/优化器状态，不等于激活梯度
无需计算图。不要为了适配显存默认量化；不要在本批安装 GPU extra 到 Mac。

[官方权重索引](https://huggingface.co/Qwen/Qwen2-VL-7B-Instruct/blob/main/model.safetensors.index.json)
列出的张量总大小 16,582,751,232 bytes 不是完整运行显存，不能据此承诺 24/32GB 适用。
[NVIDIA 官方 4090 标准配置](https://www.nvidia.com/en-us/geforce/graphics-cards/40-series/rtx-4090/)
为 24GB；历史用户节点报告 49,140 MiB。未来若选择同类平台规格，核对实际单卡容量与
稳定性保障，不从营销名称继承设备事实。

## 4. 每次运行的来源链与保存

公共运行层已能记录配置、代码/依赖、seed、状态和耗时；本批新增组件须补齐其有效来源：

1. **代码**：commit、相关 dirty 状态/改动、真实入口和命令。没有实现的入口不提供假命令。
2. **依赖**：项目锁文件、Python、模型依赖版本、驱动/CUDA、GPU 和 attention backend。
3. **模型**：checkpoint 与 processor 的各自来源/revision、dtype、模板、实际视觉 token 数。
4. **数据**：生成器版本、seed、完整对象/RGB/bbox 和问题清单、family ID、划分与追加是否启用。
5. **接口**：零起点 block 层、query/KV head、物理 token/slot、mRoPE 前后、mask、完整分母、
   donor、重算范围及端口顺序。
6. **结果**：逐输入 greedy/candidate 结果、聚合统计、失败、attempted/succeeded/failed 计数、
   各段耗时、峰值显存、产物位置和工程误差分布。
7. **解释**：报告链接真实 run ID；区分数据/实现失败、科学反例、未确定和等价合并。

改变输入、端口、donor、精度、模板或后端后，不能无条件继承旧缓存或校验证据。
Git 只保存代码、小配置、协议和有依据的解释；`data/`、`runs/`、权重与大激活不提交。
重要产物独立备份，尤其不能只留在临时 GPU 磁盘。

本批默认 tracking/artifact 上传关闭。需要 MLflow 时仍先保存本地记录，上传失败明确标记，
不影响本地结果留存。服务地址与认证使用批准机制；凭据、整个环境变量集合和私有数据
不进入日志或 Git。此前真实 OSS 文件链路仍待验证，不在本批接入义务中。
