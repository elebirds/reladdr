# E02 v1：目标位置与答案属性的因果区分

2026-10-20。P1 主复现，实验组 E02；主入口 `reladdr.experiments.e02`。
目标是恢复一个可用的目标选择/属性读取端口，随后逆向追踪动态参照如何产生选择。

## 前作具体做了什么

[R3 §5.1](https://arxiv.org/html/2603.22278v3#S5.SS1) 与
[作者 patch.py](https://github.com/Nix07/spatial-variable-binding/blob/main/last_token_exp/src/patch.py)
逐层移入 donor 的最后位置残差。作者代码实际替换聊天输入的 `-1`，并在同处读下一 token；
不是按图示中的单词 is 定位。A.3 明确追加 generation prompt。主复现用实际 readout；
问题末词 is 单独作为端口对照，实际 token 索引和文本逐样本保存。

论文报告：Qwen2-VL-7B-Instruct 在 Squares 中，0–19 层主要保持接收图原答案，
20–22 层偏向接收图的 donor 目标位置属性，23–27 层偏向 donor 自身答案。
这个层号是对照依据，不作为本项目预设成功窗口。

## 样本和输入对齐

- 主复现 Squares 横排：336×336，56×56 正方形，间距56px，左端起点28px，中心行 y=140。
  对齐作者 `shared/experiment_config.py`、`shared/images.py`。
- 六色/RGB 与作者 `shared/palette.py` 一致：red(255,0,0)、green(0,255,0)、blue(0,0,255)、
  black(0,0,0)、brown(150,75,0)、gray(128,128,128)。系统提示与前作一致。
- 同一个中间参照；recipient 和 donor 的左右属性不同、问题方向相反；三个候选结果两两不同。
- 首批 discovery=8族、每族4对；validation/test各4族预留。扩量不重分原有族。
- 后续 Shapes 横/竖采用项目 E01 的448px场景与六色；若预算仍336px，明确记录其为适配，
  不混为逐像素前作复现。
- 数据、真值、未干预基线全量保存；只有 clean/donor 均答对的子集另作主因果曲线，报告覆盖。

## 三种结果如何区分

设接收图原答案 a，接收图在 donor 目标位置的颜色 b，donor 自身答案 c，要求 a、b、c 两两不同。
对每层实际 decoder block 输出残差、每个声明位置做单点替换并重算原生后续网络。
保存 P(a)、P(b)、P(c)、完整六色概率、词表 top-5、原生下一 token 和实际索引。
概率聚合 lower/Title 与对应前导空格四个单 token 别名，保持完整词表归一化。

蓝线式 b 响应支持位置条件化读取，但完整状态也可能搬运关系/身份；纯地址与原生算子要在 E03
继续区分。a、b、c 的结果不能单独证明地址是线性、由 MLP 生成或与场景独立。

## 原生实现与必要检查

固定既有 checkpoint/processor；BF16、SDPA、batch=1、无缓存完整 prefill。原生最终 norm 和
lm_head 只在最后位置读出。不修改 V/K-cache，不复用被干预后的旧 suffix。
保存零起点 block-post 层号；对象形状、物理 token、semantic role 和视觉 grid 均保留。

首次样本每个实际层/端口做自身替换，完整 logits 最大误差不得超过0.01；干预后无钩子恢复检查同样执行。
钩子用 context manager 清理，异常也清理；不允许形状广播。失败输出逐条保留。
统计以场景族 bootstrap；多对共享同图不当成独立重复。

## 如何推进

- 获得内容/位置响应可区分的端口：进入 E03 的同关系、变参照路径追踪。
- 只出现直接答案：先检查参考输入和端口，再找更早的选择路径；不为制造中层峰调幅度。
- 对已声明条件出现不同路径：按条件记录，保持核心问题，不强求统一层号。
- 只有 probe/几何拟合：不足以进入 E03c 的原生算子解释。

本次执行为 discovery。validation 选择接口/维度等后才做冻结 test；测试结果不得用于重新挑层。
