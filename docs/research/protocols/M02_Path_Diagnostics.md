# M02_Path_Diagnostics — 恢复效应与条件写入诊断

阶段 P2；旧 E03b。两个 case 均已实现并执行，包括原先冻结的 validation/test。
完整指标在 [实测报告](../../reports/e02_e03_2026-10-20.md)；原生组合计算仍待 M04–M09。

## case：suffix_mediation / e03b-mediation-v1

**问题：**哪些位置组参与已观察到的后缀位置迁移恢复？竞争解释包括多位置控制、参照属性泄漏及角色兼容性。

**数据／端口：**沿用 M01 一维 v2 的16对、原28层 no-cache 实现；discovery 检查16–20层，冻结第17/18层。
把完整后缀互斥分为 vision_end、参照颜色＋square、参照后问题尾部、assistant边界／标记、关系词、其他词。
逐样本保存真实索引与 token 文本，分组覆盖完整后缀，不修改视觉token。

**操作／重算：**`group_only` 只移入一个 donor 组；`full_except_group` 移入完整 donor 后缀，再恢复该 clean 组。
都替换 block-post，重算后续各层。后一操作测对混合恢复效应的依赖，不是 clean 自然路径的单边必要性。

**指标／出口：**全量与双端正确子集的 a/b/c greedy 和概率、覆盖、按族区间。
组恢复改变效应只支持该恢复条件中的依赖；单组成功不是纯地址证明；失败也不能排除分布式地址。
因沿用 b=接收图参照色的配对，角色混淆随结果一同保留。不同组不能据此分别命名为 R、U 或关系算子。

## case：conditional_freeze / e03b-conditional-freeze-v1

**问题：**保持新问题输入时，指定文本组件的旧条件写入会怎样影响新选择？

**数据：**同图改关系用三对象横排；同图改参照用2×2同关系；原图不跟着问题改变。
保存两种自然基线及全部结果，不按冻结成功筛样本。

**端口／重算：**文本范围为 vision_end 之后，不含视觉token与vision_end。
将全部文本MLP、16–22层文本MLP、全部文本attention输出分别替换为旧问题值；参数始终冻结。
从每个实际写入端口重算残差、同层剩余组件和下游，不冻结未声明的输入。

**指标／出口：**新答案保持、旧答案返回及其他输出分别记录；只看新正确率下降不足以区别旧条件保留和一般损伤。
全MLP结果同时包含条件传播、选择和属性读取；attention操作影响跨token通信。
支持“旧条件写入控制响应”不定位地址变换。混合冻结损伤不能单独证明某组件执行仿射算子。
若新选择保持，只说明这些写入无需随条件改变，不能声称原网络完全不用该组件。

## 依赖、成本与停止

这两个已完成诊断为 M04/M05 提供候选位置，不要求重新跑全扫描。
只有新端口或新语义改变旧证据的适用性才补对应检查。历史调用数见报告，不把多个同族问题当独立样本。
后续若只增加后缀组／层而没有具体原生计算问题，停止该扩量，转向 M04 的消费接口。

实现包为 `reladdr.experiments.m02_path_diagnostics`，子命令 `mediation`、`freeze`；
当前只接受 `M02_Path_Diagnostics`，版本为 `m02-suffix-mediation-v1`、`m02-conditional-freeze-v1`。
旧模块和配置已移除；上文旧版本仅标识已执行证据，历史run来源不变。
