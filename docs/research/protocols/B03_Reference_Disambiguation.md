# B03_Reference_Disambiguation — 解除方向、目标与参照位置的混淆

协议版本：`b03-four-squares-v2`，2026-10-20。**计划，尚未实现或执行。**
B03 是新增行为鉴别，不是旧 E03a run 的改名。旧三对象及二维接口结果归
[M01/M02 的历史证据](../../reports/e02_e03_2026-10-20.md)。
总调用预算与执行授权只在 [08 首批清单](../08_resources_and_reproducibility.md) 汇总。

## 1. 本项决定什么

在同一张四对象图上，模型能否随参照和关系选择不同目标，并对不同描述指向同一目标给出
一致答案？先获得不依赖三对象中央参照、且没有多对象同侧语义歧义的自然行为样本，
再按预注册规则选择 M04 正确配对与错误诊断锚点。M04 先使用已有 pre-O/MLP 端口；
完整 Q/K/V 观测按选定消费者的需要开发。

本项不做 activation patch、不拟合地址、不定位层/头，不检验跨图状态兼容性。六种合法组合
全部用于发现，后续不得把其中任何一种称为“未探索组合留出”。新的场景族和未用于拟合的
干预可用于冻结检验；结构组合外推须另行预留真实未探索的合法域。

## 2. 固定输入

### 几何与语义

- 白底 RGB 图，`336 × 336`，四个同形正方形，bbox 采用左闭右开坐标。
- 对象 `object-0` 到 `object-3` 从左到右排列。每个边长 56 px；x 起点为
  `14, 98, 182, 266`，y 范围为 `[140, 196)`；相邻间隔 28 px，左右边距各 14 px。
- 语义为同一直线上的**立即相邻对象**，无空位、环绕、斜向、最近像素距离或并列候选。
  首批不加整体平移、垂直布局或提示变体；需要时以新协议版本单列其作用。
- processor 固定为 `336 × 336` 输入预算。预期合并后 144 个视觉 token；必须记录实际
  `image_grid_thw`、视觉索引和 token 数，不把预期数当测量结果。

六种问题按下列顺序写入清单，索引均为零起点：

| question_index | 参照、关系 | 目标 | 鉴别作用 |
| --- | --- | --- | --- |
| 0 | `(1, left)` | 0 | 内部参照的配对对照；仍与“left 取最左”一致 |
| 1 | `(1, right)` | 2 | 内部反极值：正确目标不是最右对象 |
| 2 | `(2, left)` | 1 | 内部反极值：正确目标不是最左对象 |
| 3 | `(2, right)` | 3 | 内部参照的配对对照；仍与“right 取最右”一致 |
| 4 | `(0, right)` | 1 | 与问题 2 指向同一目标；边缘参照朝内 |
| 5 | `(3, left)` | 2 | 与问题 1 指向同一目标；边缘参照朝内 |

四个内部问题中只有问题 1、2 直接反驳固定极值捷径，不能把四者都称为反极值条件。
所有六问一起才提供完整的改参照、改关系及同目标碰撞。

### 模板、读出与模型

固定系统提示：

```text
You are a helpful assistant. You respond in one token.
```

问题模板沿用已执行的 immediately 版本：

```text
The color of the square immediately to the {left|right} of the {reference_color} square is
```

图像在 user 问题文本之前，追加 assistant generation prompt。使用固定本地
Qwen2-VL-7B-Instruct，权重 revision
`2cbada593a2b4c785cd4b8bbb27d7a3f50d45b70`；processor 来源另行核对记录，不从权重 revision
推定。冻结参数、BF16、SDPA、batch=1、无量化、无缓存完整 prefill，原生最终 norm 与 lm_head
在物理最后位置读取一个 token。它不是问题末词 `is`；保存实际末位置文本和索引。
沿用 Torch 2.8.0、Transformers 4.57.1；运行前记录实际 CUDA/驱动和依赖，不自动换版本。

主结果为完整词表的实际 greedy token，经预定大小写/空白规范化后的颜色答案；另外保存
六色别名聚合概率、`candidate_prediction` 和 top-5。候选 argmax 不替代实际 greedy。
六色均检查 `{lower, Title, " "+lower, " "+Title}` 在实际提示边界上为单 token；
不同颜色的 token 集不得重叠，失败时停止，不静默删色或取多 token 答案的首项。

## 3. 场景族、配色与固定规模

使用已有论文调色板的名称、顺序和 RGB：

```text
red=(255,0,0), green=(0,255,0), blue=(0,0,255),
black=(0,0,0), brown=(150,75,0), gray=(128,128,128)
```

这是 `tasks/patching.py` 的 `PAPER_PALETTE`，不是旧 smoke 的另一套六色 RGB。
每张图四种颜色唯一。六色池也为 M04 留出两个未占用色；“四对象”不等于只能使用四色。

### 原图与派生图共用所有权清单

v1 的独立原图配色规则遗漏了 M04 派生图。只读复算确认：启用旧追加池后，4 张 M04
换色图、6 个完整输入变体跨父族重合；这是计划冲突，不是实测数据。v2 取消旧 `16+16`
配额和配色平衡优化，先为每个父族预留完整合法单换色闭包。

规则中的颜色都使用上述索引 `0..5`，不通过输出或图像文件 hash 选取：

1. 枚举全部无重复的有序四色元组 `a`。伙伴为 `b=tuple((x+3)%6 for x in a)`；
   `pair=tuple(sorted((a,b)))` 规范化后去重，共 180 对。
2. `pairs=sorted(unique_pairs)`，用 `random.Random(20261020).shuffle(pairs)` 固定优先序。
3. 对每对计算 `closure(pair)`：两张原图，以及各图每个位置分别换成任一未使用色的全部
   合法变体。每对闭包恰为 18 张图；对象位置、形状和其余颜色不变。
4. 从空的 `occupied` 顺序扫描全部 180 对；只有闭包与 `occupied` 无交集时才接纳，
   并将整个闭包加入 `occupied`。扫描结束即结束，不换 seed 或搜索更多族。
5. 按接纳次序编号。独立 `random.Random(20261021)` 对每个接纳族调用 `getrandbits(1)`：
   0 取规范化 pair 的第一元组为 c0，1 取第二元组为 c0；另一张为 c1。

上述确定性组合规则的只读复算得到 **9 族、18 张原图、162 张互不跨族的闭包图**。
它是顺序极大装填，不声称最大容量；原图在各位置的六色频数为 2–4，仅报告配色分布。
闭包预留不表示要渲染或执行 162 张图。首批 B03 只运行 18 张原图的六问，即 **108 个自然输入**。
不存在旧追加池；需要更多证据时，根据具体区分预测另登记下一批。

当前 family ID 为 `b03-v2-s20261020-f0000` 至 `f0008`，均属 `discovery`；
原图 scene ID 附 `-c0` 或 `-c1`。闭包只从两张原图各做一步换色，不递归扩展。
任一族／配色都可成为 M04 的结果分层锚点，不改变已经确定的所有权。

统一 manifest 至少维护：

- 图像的对象 ID、颜色/RGB、精确 bbox，以及唯一 `image_id`、`family_id`；
- 原图／派生图关系和变体角色，同一图可承担多个角色；
- 完整提示与唯一 `input_id`，同图同提示合为一个输入，不同问句分别保留；
- 运行条件与已取得输出／张量的可复用记录。

未来 validation/test 必须连同其派生图一起与此所有权清单比较，再划分场景族。
未被执行的闭包图已有 family 归属，不能以“未运行”为由挪到另一个划分。
若新增非闭包变体碰撞其他族，先避让或合并其连通分量，再重算覆盖与统计单位。

## 4. 离线实现与验收

现有 `tasks/relational.py` 的 horizontal 布局固定为三对象，中心坐标与部分绝对位置问法
也依赖原布局；现有 `make_grid_move_pairs` 是二维 donor 配对。**不能仅给现有配置
填入“四对象”就声称 B03 已可执行。**

后续实现者应复用现有 dataclass/绘图和原生 adapter 的明确契约，新增本协议的真实生成与
记录入口。当前入口采用新版 canonical 编号；历史 run/报告与 snapshot 保留原数据科学含义，
不为旧模块路径提供兼容入口。本页不提供尚不存在的执行命令。

模型运行前完成以下离线检查：

- 首批恰为 9 族、18 张原图、108 个唯一输入；闭包预留图不是额外自然前向。
- 检查 9 个完整闭包两两无交集、总计 162 张；原图与派生图都只有一个 family 所有者。
- 每图四个对象、唯一颜色、精确 bbox、无裁切；六问 target=`reference±1` 均合法。
- 两个同目标碰撞分别成立；内部问题 1、2 与极值捷径答案不同；各问题参照存在且唯一。
- `c0/c1` 的位置目标不变、答案跟随实际颜色；预先写出全部真值，不沿用旧答案。
- 重复变体角色合并到同一 image/input 记录；来源清单与新输入／重捕获计数一致。
- 在选定的四个代表性 family 上检查实际渲染，覆盖六色、边缘参照及两种配色；检查字体
  或标记没有被意外绘入模型输入。预览只用于人类验收，不作为额外输入。
- 对生成器、配对统计、预算计数和即时记录写 CPU 测试；导入不加载 GPU 栈、不下载模型。
  B03 的真实 processor/token 边界检查在获准执行前完成；只验收当前实际使用的写入端口。

本轮仅做内存中的组合复算，未实现生成器、创建研究数据或调用模型。

## 5. 评价与推进门槛

保存全量 greedy/候选结果，按六组合、配色、内部反极值/内部对照/边缘参照切片。
将 greedy 颜色映射回本图唯一对象位置；无效 token 或图外颜色单列，不能当作某个对象误选。
直接报告固定方向取极值这一行为捷径的预测及匹配数，不把匹配等同内部机制。

六个预定配对类型均在同图同配色内定义：

1. 问题 `0↔1`：参照 1 不变、改关系。
2. 问题 `2↔3`：参照 2 不变、改关系。
3. 问题 `0↔2`：left 不变、改参照。
4. 问题 `1↔3`：right 不变、改参照。
5. 问题 `4↔2`：不同参照/关系、同目标 1。
6. 问题 `1↔5`：不同参照/关系、同目标 2。

对每类配对，记录双端 greedy 正确的配色数及其覆盖的独立族数；每族任一配色合格就为该类
提供一个族，不把两个配色计为两族。另记录同问题跨 `c0/c1` 正确且跟随换色的覆盖。
accuracy 和配对一致性区间按 scene-family 重采样 1000 次，bootstrap seed=`20261022`；
报告族数/问题数和完整分子分母，不按模型表现删除输入。

### 覆盖报告与锚点选择分开

六类配对的正确族数是行为覆盖报告，不再要求全部达到四族才能研究某个已有的正确计算。
M04 按其预注册规则从本批实际结果选正确配对锚点，并另选错误诊断锚点；完整 B03 结果
保留。因果锚点可代表成功子集，不能据此报告全域准确率。

- 内部反极值成功实例约束“只按方向取极值”的解释；同时报告错误和边界策略匹配。
- 若成功配对覆盖有限，针对已有锚点研究，明确缺少的方向／参照条件；不自动扩量凑比例。
- 若反极值条件稳定输出边界，可研究实际错误策略；按错误样本的操作定义推进，而非改其真值。
- 图外颜色、无效 token、输出对应参照等情形单列。颜色对应对象不是内部读取对象的直接测量。
- 若几种算法都能解释六问，记录待辨识的竞争解释；在 M06↔M07 中安排有分歧预测的比较。
  当前行为不可区分不等于原生机制等价。

没有可用锚点时，交付行为与具体缺口；下一批资源由新增证据或区分预测决定。
真值、token、记录或 hook 检查失败则先停止受影响调用、修复实现；技术失败不计科学错误答案。

## 6. 产物与解释范围

后续入口应逐输入保存：有效配置、模型/processor 来源、family/scene/question 清单、实际图、
prompt/chat template、token/role 映射、真值、greedy/top-5/候选概率、失败及真实调用计数。
运行中即时保存结果及尝试账本；重复捕获记成本但不增加新输入或族数。tracking 和 artifacts 上传关闭。

B03 给出哪些实例确实需要动态参照、哪些仍符合边界策略的行为记录，仍允许序号移位、
候选比较、邻接表读取及其混合。它不是“发现地址”的结果；下一项工作是从原生属性消费端
追踪选择计算，而不是再扫一遍四对象全状态移植。M03/M04 如何承接见
[总实验树](../06_experimental_design.md)。
