# 原生接口与符号：状态、来源贡献与实际写入

## 1. 固定模型执行条件

首个实验模型为 [Qwen2-VL-7B-Instruct](02_related_work.md#c1)。设图像前缀在问题之前，
语言主干严格因果。后来的关系词不能改变已经计算的前缀状态；问题条件只能经后续查询、
文本侧中转或对预存场景信息的读取发挥作用。

这个边界依赖实际序列和 cache 执行顺序。插入 token、改 chat template 或重算前缀时，
要重新核对位置，不能只依据自然语言描述判断“问题在前/后”。

## 2. 主要符号

| 符号 | 含义 |
| --- | --- |
| $I,q,\rho$ | 图像、问题、当前关系条件 |
| $\ell,h,g(h),t,j$ | 语言层、query 头、其原生 KV 头、读取 token、来源 token |
| $\mathcal V$ | processor 后进入语言主干的视觉 token 索引集合 |
| $B_{\mathrm{ref}}$ | 参照条件视觉读取状态；可能混有位置、身份和场景信息 |
| $U_R,R,E$ | 候选空间基、投影坐标、投影余项 |
| $C_{\mathrm{scene}}$ | 余项及其他路径提供的场景信息，不是干预集合 |
| $U_{\mathrm{target}},U_U$ | 目标地址成分的坐标、对应输出接口的基 |
| $b_{u,v}$ | 经独立标定的场景内地址码，不预设为像素坐标 |
| $T_\rho(r)=A_\rho r+t_\rho$ | 待检验的关系条件仿射地址算子 |
| $G_i,C,k$ | 原生缓存干预组、被选组的集合、恰好选取的组数 |
| $Y_q(C),D_q$ | 完整受影响注意力接口、接回原模型的下游计算 |
| $M_q,J,\widehat J_r$ | 固定正确/foil 答案优势、真实联合目标、某轮代理 |
| $s=(q,h,t)$ | 一个问题、头、读取位置构成的响应行 |

下文统一用 $C$ 表示集合、$C_{\mathrm{scene}}$ 表示场景条件，避免同字母隐藏依赖。

## 3. 先定义原生参照读取状态

在候选参照描述 token $t_r$，考察头集合 $H_b$ 的视觉来源贡献。它是待定位的一个候选端口，
不预设每种模板都在这里完成绑定；完整原生状态先于低维分解检查：

$$
B_{\mathrm{ref}}=
\operatorname{concat}_{h\in H_b}
\left[\sum_{j\in\mathcal V}\alpha^{\ell_b,h}_{t_rj}
 v^{\ell_b,g(h)}_j\right].
$$

这是注意力输出的可计算分量，不是新加给模型的网络。干预时需要声明怎样将分量变化注入
对应的原生头输出并经 $W_O$ 传播，同时保留其他来源。候选层/头属于要定位的对象。

$B_{\mathrm{ref}}$ 可能含参照身份、颜色、其他对象排序、预存关系，甚至较晚阶段的目标信息。
在参照先于关系的模板中，若取样位置确在关系词之前，可排除它依赖尚未出现的当前关系，
但不能排除它携带所有方向的预存邻居。参照先行是辅助模板，不能代替论文主模板；
关系到达前没有取得独立 R，不构成原生关系计算不存在的证据。

取正交列基 $U_R$，定义：

$$
R=U_R^\top B_{\mathrm{ref}},\qquad
E=B_{\mathrm{ref}}-U_RR.
$$

投影只是候选空间成分；$R$ 不自动纯净，$E$ 不自动非空间。构造基时比较“同对象换位置”
与“同位置换身份/场景”，并将 $E$ 和其他输入路径保留在 $C_{\mathrm{scene}}$ 中。

## 4. 输出接口不能与输入接口直接混同

目标地址若可独立辨认，可出现在不同层/token/组件。其独立性与存在均待检验；候选竞争后
直接读属性也是允许路径，此时以 QK 分差、选择权重与原生写入作输出，不人为增加 U。
对于可标定的目标成分，定义：

$$
U_{\mathrm{target}}=U_U^\top(h_{\mathrm{target}}-c_U).
$$

输入 $R$ 与输出 $U_{\mathrm{target}}$ 可能处于不同坐标系。跨阶段的基与地址原型要使用
独立定位数据标定，不能用待检验的关系答案自由对齐每张图。

比较 $U\approx A_\rho R+t_\rho$ 时可以声明输入/输出两套基；要检验逆变换或交换律，
还必须先将它们对齐为**同一个地址空间上的自映射**。不能直接复合两个不同端口的矩阵。
若地址体系依赖场景归一化或对象排序，这个坐标系形成过程也是解释对象。

“目标地址状态”与“某组件新写入的地址增量”也分别记录。若原地址经残差保留，不能把完整
输出状态全部归为该 MLP/头的写入；增量模型与状态模型使用相应的目标变量。

### 已有实测对接口的约束

[2026-10-20 E02/E03](../reports/e02_e03_2026-10-20.md)在R3锚点恢复了末位置的位置/属性阶段，
但动态参照对照中完整suffix与单readout响应不同。原生残差h_ref、问题尾部及assistant组参与恢复；
它们不是本节定义的视觉来源分量B_ref，更不能直接命名为纯R/U。
二维排除了预期位置色与参照色重叠后仍有位置迁移，故也不能由一维移植失败断言地址不存在。
输出接口先由 M04/M05 的实际消费路径确认，再作为 M07 的解释对象。
M01 的地址中继只是跨上下文语义的辅助分支，不是取得输出接口的先决条件。

### 原生组件端口与实现状态

block 内计算顺序为残差输入 → RMSNorm1 → Q/K/V 投影 → Q/K 的 mRoPE → attention →
pre-O 头输出 → W_O → 残差相加 → RMSNorm2 → MLP → block-post。
语言层号固定为零起点 block-post 0–27，不含独立 embedding 槽；
readout 为追加 generation prompt 后的物理末位置（换行），问题末词 is 是另一个端口。

| 端口／能力 | 当前实现 | 干预后科学上必须重算 |
| --- | --- | --- |
| block-post 残差 | 已实现 | 后续层及最终 norm/head |
| attention-write | 已实现，W_O 后加残差前 | 残差、同层 MLP、后续层 |
| pre-O query-head 输出 | 已实现，支持逐头 | W_O、残差、同层 MLP、后续层 |
| mlp-write | 已实现，加残差前 | 残差合并及后续层 |
| Q/K/V 投影整行 | 已实现；Q/K 为 pre-mRoPE | 旋转、attention、同层剩余计算、后续层 |
| post-mRoPE 捕获、完整分数／来源分解 | M03 的 reader_attention，候选确定后实现 | 观测本身不改计算；合成输出写回见下文 |
| 单 Q 头／原生 KV 头投影干预 | M03 的 native_nodes，按需实现 | 原生 attention 与全部受影响下游 |
| receiver 私有输入边、MLP gate/up、激活梯度 | 路径需要时再实现 | receiver 自身 norm 与计算、下游 |
| 读取时 K-cache 编辑、部分重放 | S01／性能能力，未实现 | 见第5节，不冒用整前向的语义 |

现有参考执行每个 trial 都完整 prefill、`use_cache=False`。表中是因果重算范围，不表示已实现从中间层快速重放。
M04 初筛和局部确认使用已有 pre-O/MLP 写入端口；只有 M05 需要来源竞争时才补 Q/K/V
观测与重建。新端口按实际消费者验收，不要求先完成所有 M03 能力。

Qwen2-VL 当前为28个 query heads、4个原生 KV heads；映射读模型配置，不在实验脚本写死。
修改一个原生 KV 槽必须影响共享它的全部 query heads；只改展开副本应称特定读取边。
pre-mRoPE donor 移到 recipient 位置后使用 recipient 旋转；post-mRoPE donor 已携带原旋转，二者分开记录。

### 全来源分母与来源贡献

对完整可见序列计算：

$$
z_{tj}=\frac{(Q^{post}_{t,h})^\top K^{post}_{j,g(h)}}{\sqrt{d_h}}+m_{tj},
\qquad
\alpha_{tj}=\frac{\exp z_{tj}}{\sum_{k\in\mathrm{visible}(t)}\exp z_{tk}},
\qquad C_A=\sum_{j\in A}\alpha_{tj}V_{j,g(h)}.
$$

来源包括视觉、系统文字、问题、vision_end、user/assistant 边界等；同图不保证文本 K/V 不变。
各互斥来源的 C_A 之和恢复原生 pre-O 输出。对象 bbox 内 token 也可能含全局信息，背景不是默认无关来源。

- 测量 C_A 不改变网络。
- 注入 `Y'=Y-C_A_clean+C_A_donor` 是 pre-O 来源贡献干预。
- 改 K 或分数并重算会改变完整分母及其他来源权重，不等于只替换 C_A。

候选组 C 内部的条件权重 P(j|C) 需连同来源注意力总权重 m_C=Σ(j∈C)α_j 和完整 Y 记录。
候选 logits 同加常数虽不改 P(j|C)，却可改变相对文本／特殊 token 的注意力总权重及 OV 写入。
只有整个可见来源集合上的共同 logit 平移才保持整行 softmax。

完整分母是实现契约，不要求每个局部解释预测所有背景 token 的逐项分数。解释应登记
哪些条件变化、候选对比和写入由它预测，哪些原生项仍作为条件给定；最终检验对应的总权重、
实际写入及下游效应。M04 尚无来源分解时只报告写入变化，不虚构 source mass。

### 行级合成输出与节点级干预

M05 默认固定 recipient 上下文，用两次自然运行的实际 Q/K/V 重建声明行/头组的交叉输出，
只写入该处 pre-O；其他同层输出保持 recipient 原值，再重算原生下游。
名称前缀为 `row_output_`。它不改原生 K/V 节点，同层其他共享头不会自动改变。

`native_node_` 则改变原生 Q/K/V 投影或缓存槽位，并允许它影响全部实际读取位置。
两类操作的 donor、mask 和下游作用域分别记录，不合并成一种“Q/K/V patch”。
默认行级方案及 `2PC` 预算的具体含义见 [M05](protocols/M05_Selection_Carrier.md)。

### 节点、中介与直接边

节点输出替换影响全部后代；“改 sender → 捕获 receiver → 在 clean 回放 receiver”测经 receiver
汇集的中介，包含所有 sender 到 receiver 路径，不能叫作隔离的直接边。
若 sender 确为 receiver 残差输入中的加性项，receiver 私有输入可定义为
`x_R'=x_R_clean-s_S_clean+s_S_cf`；其他 receiver 仍取 clean 输入。
必须重算该 receiver 的 RMSNorm 和投影，不能只将 Δs 乘固定矩阵。跨 token 边还要区分分数竞争与 value 来源。
Q/K/V 交叉、私有边和分量注入均可能产生混合状态；结合自然变化与预先预测解释，成功不自动证明自然使用，
失败不单独否定机制存在。

## 5. K-cache 搜索的干预对象

固定一层 $\ell$，对原生 KV 头与视觉 token 定义互不重叠的组：

$$
G_i=\{(\ell,g,j):j\in\mathcal T_i\},\qquad G_i\cap G_{i'}=\varnothing\ (i\ne i').
$$

首版只替换 **mRoPE 后、GQA 复制前的 K-cache**，V 保留。固定一个网格和位置编号匹配
的 donor 前缀；每组的替换值在搜索期间不变。同一原生 KV 槽位会影响读取它的全部 query 头，
不能只改某个复制品并称为改了原生槽位。模型参考配置中每个 KV 头对应 7 个 query 头。

执行顺序：图像前缀 prefill → 修改选中层视觉 K → 固定问题 suffix prefill → 下一答案 token logits。
只改该层缓存时，该层文本输入来自未改变的更低层，因此该层 Q 和文本 K/V 对集合保持固定。
后续层受影响的文本状态和缓存必须重算；已完成的图像前缀是这项**读取时干预**的固定条件。
这与重算整张图像的组件删除是不同因果问题。

## 6. 接口充分性的条件

定义 $Y_q(C)$ 为该层所有受影响的 query 头、所有受影响 suffix token 的 attention 输出，
放在原生 $W_O$ 之前。除这些行外的固定信息记为 $H_{q,\mathrm{fixed}}$，则固定问题的
下一 token 目标可以写为：

$$
M_q(C)=D_q(Y_q(C);H_{q,\mathrm{fixed}}).
$$

这里 $D_q$ 包括输出投影、残差、MLP、后续层和答案读出。相同 $q$ 与固定状态下：

$$
Y_q(C_1)=Y_q(C_2)\ \Longrightarrow\ M_q(C_1)=M_q(C_2).
$$

只缓存最后一行通常不充分；某个 key 可先改变更早问题 token，再传至最终答案。
跨问题的 $D_q$ 与固定状态不同，不能直接使用上述等价关系。自由生成还会引入未来读取
和变化的 token，首版不把仅有 prefill 的接口称为整段生成的充分状态。

## 7. 所有实现必须携带的端口说明

记录层、token 的物理索引与语义角色、head/KV 分组、processor 后映射、pre/post-RoPE、
缓存还是残差干预、donor、重算范围、dtype 与 attention backend。机制线与搜索线可以使用
不同端口，但方法比较要先对齐这些条件。
