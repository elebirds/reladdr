# 背景：从“找到空间 ID”推进到“解释关系怎样使用它”

## 一个具体例子

给定一张含多个对象的图，问：“红色圆形正左侧物体是什么颜色？”

模型必须把描述绑定到参照对象，用“左侧”确定目标，再读取颜色。答错可能来自对象识别、
参照定位、关系执行、目标写入或属性读取；单个准确率无法区分。即使某层可以解码位置，
也仍不知道当前关系如何使用该位置。

这项研究服务于需要可验证解释的 VLM 研究者：把模型的选址与读取过程恢复到可预测的
计算链，解释同一类空间任务中的成功与失败。选择性修复或准确率提升可以成为后续用途，
当前的核心收益是对原生计算的理解。

## 已有工作形成了怎样的积累

研究首先从**视觉绑定**出发：怎样把对象的颜色、形状等特征归属于同一个对象，而不是混合。
[Visual Symbolic Mechanisms](02_related_work.md#r1) 用位置 ID 与因果干预描述获取、选择和
特征读取阶段，且在 §4.4 已测试直接方向关系下的颜色读取。这个任务和“空间 ID 可跨任务复用”
都是前作基础，不能作为本项目新贡献。

随后，研究深入**视觉空间信息怎样进入语言计算**。
[Linear Mechanisms](02_related_work.md#r2) 提取对象词中的空间成分并进行干预；
[Dual Mechanisms](02_related_work.md#r3) 分析视觉排序信号及语言主干的补充作用。
这些方法给了可复用的地址候选与来源定位工具。

再进一步，空间关系还涉及**对象在问题中的角色与实际读取路径**。
[Who Is Left of Whom?](02_related_work.md#r4) 检查位置交换、角色翻转与源端到查询端的信息传播；
[Visual Retrieval Heads](02_related_work.md#r5) 与
[Matching Object or Relation?](02_related_work.md#r6) 为读取和关系相关组件提供定位方法。
因此，“存在关系表示”“找到重要头”也不是足够的新问题。

## 现在要推进哪一步

本项目的问题是：**在已经取得参照空间信息之后，当前关系通过哪些原生运算改变候选选择，
并形成可被属性读取使用的目标地址？**

具体希望补上三件事：

1. **依赖范围**：形成选择状态前，使用了参照、关系和哪些额外场景信息？
2. **计算内容**：是共享地址变换、候选比较、预存邻居读取，还是这些依赖的组合？
3. **可预测性**：一个紧凑解释能否预测留出条件下的 QK 分数差、地址写入及实际误选？

这是沿现有方法继续恢复内部计算，不以“暂时没找到同名工作”作为价值依据。对其他论文
未逐组件研究的部分，只表述为当前方法的延伸目标，不推断整个领域都没有相关结果。

## 两种目标不能混用

**机制目标 M** 是恢复计算依赖。我们不必比原模型更会答题，也不能用一个外部小模型能
完成任务来代替原生运算证据。

**方法目标 S** 是更有效地搜索有限干预集合。单项评分可能遗漏联合效应，但
[AtP*](02_related_work.md#r10)、连续掩码优化和分式规划已有基础。要推进的是特定原生
接口下的精确联合响应如何帮助真实行为搜索，而不是重新宣称“联合优化”有价值。

## 研究边界与当前选择

- 首个分析对象：Qwen2-VL-7B-Instruct；它与近邻任务和可追踪的因果前缀接口衔接。
- 初始机制任务：直接方向关系、目标唯一的受控场景；不把最近邻、空位和不规则布局混成一题。
- 首要机制假说：场景地址结构可预先形成，关系在语言侧触发共享的仿射地址变换。
- 首要算法对象：同图多问、固定层、原生视觉 K-cache 的 K-only 替换。
- 当前只建立工程和文档，所有模型现象与性能收益仍待实测。

设备选择影响执行规模，不决定问题的重要性。某个线性/仿射配置失败，不意味着关系寻址
不值得研究；应依据具体反例继续检查候选、场景或其他路径。
